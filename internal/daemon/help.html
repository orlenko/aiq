What it does

You have several paid Claude Code and Codex subscriptions. aiq puts a claude and a codex shim first on your PATH; every call (your interactive sessions, claude -p and codex exec workers, and the workers those agents spawn) is routed to the account that is about to waste the most quota, then the real CLI runs with that account's credential. Nothing in your prompts or scripts needs to know which subscription it is on.

Each account is an overlay home: a CLAUDE_CONFIG_DIR or CODEX_HOME made of symlinks into your real ~/.claude or ~/.codex, so settings, plugins, sessions and history are shared and --resume works on any account. Only the credential and .claude.json are private per account.

Reading the status page

One column per provider, one card per account, in the order set by aiq account order (the [display] order list in the config file). The pill in the corner says what routing thinks of it right now:

#1 · 23.7/hEligible for workers; rank and score (percentage points that vanish per hour if idle). #1 is the next pick.
no loginThe overlay home has no credential yet. Run the command shown under the title: aiq account login <provider>/<name>.
no poll grant … (red note)A Claude account whose quota cannot be read yet: aiq account authorize claude/<name>.
weekly window exhausted until …A binding window is at 100%, or a worker was rejected with a usage limit. The account is skipped until that time.
at worker cap (3) / weekly … ≤ reserveFine for interactive use, skipped for workers right now.
disabledYou disabled it; aiq account enable … brings it back.

Bars are usage; dim names are windows that do not bind (a model-scoped cap for a model that is not your default). Below the bars: reset countdowns, reset credits, and the last time telemetry arrived. Blue rows are live leases: interactive sessions and worker runs, with pid and working directory; d1 means a nested call one level deep. The grey monospace lines are the score terms.

next pick shows the full ranking for each provider and mode, with every term, so a surprising choice can be traced. events is the audit log: launches, exits, limit hits, imports, overlay adoptions.

poll now asks the daemon to poll every account immediately instead of waiting for the next tick.

For scripts, aiq status --json and GET /api/state return the same document (schema_version 1): per account eligible, ineligible, exhausted, score, worker_slots, windows with used_pct and resets_at; per provider worker_capacity, the number of workers a fleet can launch right now.

Day to day

Use claude and codex as before. On an interactive launch aiq prints one line, aiq: using claude/work — 5h 43%, weekly 8%, and the session keeps that account for this git checkout until a window crosses the switch threshold. Workers are silent on success.

When a session hits its limit mid-conversation: quit, run the same command again, and aiq picks another account. Your transcript is shared, so claude --resume or codex resume continues where you were.

aiq status              # the same picture as this page, in the terminal
aiq status --explain    # plus the full ranking with every term
aiq top                 # live, refreshes every 5 s
claude --next           # leave this checkout's current account
claude --account personal  # force one account (once)
AIQ_BYPASS=1 claude     # skip routing, run on your real ~/.claude

claude auth …, claude setup-token, claude update, codex login and codex logout always run against your real home, unrouted.

Accounts

aiq account list
aiq account add claude work           # overlay home + Claude Code login + poll grant
aiq account add codex work            # overlay home + codex login
aiq account login claude/work         # redo the CLI login
aiq account authorize claude/work     # redo the quota poll grant
aiq account poll                      # poll every account now
aiq account label claude/work "Claude · work"
aiq account order claude/work claude/home codex/work
aiq account enable|disable claude/work
aiq account remove claude/work --purge
aiq account use codex/work            # pin this checkout
aiq account next codex                # rotate this checkout
aiq account import                    # optional: adopt accounts from aiquota, if installed

Adding a Claude account takes two browser steps: the Claude Code login inside the account's home, then a second authorization that mints aiq's own token for reading quota (Claude Code's own credential is never read or copied). Sign in as the same account both times. Adding a Codex account is one browser login; quota is read through the Codex CLI itself, no extra step.

Sign out of claude.ai or chatgpt.com first, or use a private window, or the browser hands back the account it is already signed in as; aiq warns when two accounts turn out to be the same login.

Manual overrides when telemetry lags:

aiq mark codex/work exhausted --until 14:42   # or +2h, or RFC3339
aiq mark codex/work ready
aiq reset codex/work                          # spend an earned Codex reset credit

Long-running sessions

A session that must survive for days (a QC loop, an orchestration overseer) is started with aiq long claude or aiq long codex. It lives in a tmux session named after the workspace, and the daemon watches its account. When the tightest window drops to drain_pct remaining, aiq's hooks (attached only to sessions launched this way) inject a wrap-up instruction at the next turn boundary: finish the current unit, stop background jobs and subagents, write a handoff note, end the turn. Then the daemon respawns the same pane on the next account: the same provider resumes the transcript, a different provider starts from the note plus the working tree. An idle session is moved without waiting; an account that is already blocked is moved at once; with no headroom anywhere the session waits for a reset.

aiq long claude              # start, or attach if it already runs here
aiq long list                # lease, pane, drain state, idle/busy
aiq long drain .             # move this workspace's session now
aiq long attach
aiq long stop .

Lease rows on the cards show long and the drain state (requested, draining, ready, waiting). Notes are written to ~/.local/share/aiq/handoff/.

How an account is picked

For every binding window w of an account (5-hour and weekly, plus a model-scoped weekly cap for your default model):

remaining_w = 100 − used_w
hours_w     = time until w resets   (floored at min_hours, default 15 min)
perish_w    = min(remaining_w, remaining_weekly) / hours_w
score       = Σ perish_w × weight_w  ÷  (1 + worker leases on the account)

perish_w is the quota that evaporates per hour if the account sits idle. weight_w is 1 for the session window and weekly_weight (default 5) for weekly windows, since one weekly point is several session points' worth of tokens; that way an account whose week rolls over in a few hours with quota unspent gets the work well before the last hour. Highest score wins, so a session window with 57% left that resets in six minutes beats an account with far more weekly quota. Before scoring, accounts are filtered: exhausted (a binding window at 100%, or a recent limit hit), disabled, no login. Workers additionally skip accounts at the worker cap or with weekly remaining at or below the reserve, and prefer accounts that do not carry an interactive session. Interactive launches are sticky per git checkout until a window crosses switch_pct. Telemetry older than stale_after_seconds falls back to a neutral prior.

Troubleshooting

aiq doctorStart here. Each FAIL line names what to run.
which claudeMust print the shim under ~/.local/share/aiq/shims/. If not, the PATH line from aiq shim install is missing from your shell rc, or this shell predates it.
no eligible accountEvery account is exhausted, benched or logged out. aiq status --explain says why for each; aiq mark … ready lifts a stale bench.
stale telemetryThe header shows the last poll and any per-account error; aiq account poll runs one by hand and prints each account's result. A Claude poll that says the grant was revoked needs aiq account authorize again.
daemon log~/.local/share/aiq/log/daemon.log. Restart on macOS with launchctl kickstart -k gui/$(id -u)/dev.aiq.daemon.
overlay backupsWhen a file the CLI rewrote inside an overlay is folded back into the real home, the displaced copy is kept next to it as <name>.aiq-bak, rotating up to .aiq-bak.3.
state~/.local/share/aiq/state.db (SQLite: accounts, windows, leases, events; no credentials). Config: ~/.config/aiq/config.toml.

Config

Everything has defaults; ~/.config/aiq/config.toml is optional.

[providers.claude]
binary = ""             # real CLI path; empty = walk PATH outside the shim dir
model_scope = "auto"    # scoped weekly cap that binds; "auto" reads settings.json model

[selection]
interactive_policy = "sticky"   # sticky | score
switch_pct = 95.0
stale_after_seconds = 900
weekly_reserve_pct = 5.0
max_workers_per_account = 3
max_depth = 3                   # nested claude → codex → claude … cap
min_hours = 0.25
weekly_weight = 5.0             # weekly points count 5× session points

[worker]
retry = true
retry_max_seconds = 60.0

[poll]
interval_seconds = 300
timeout_seconds = 60

[display]
order = ["claude/work", "claude/home", "codex/work"]
[display.labels]
"claude/work" = "Claude · work"

[daemon]
listen = "127.0.0.1:7379"

[long]
drain_pct = 4.0
fallback = ["claude", "codex"]
check_interval_seconds = 30
idle_grace_seconds = 20
